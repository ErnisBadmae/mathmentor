- По разрешению владельца после ревью Opus реализованы `/timed`, правила/явный старт,
  общий лимит 5 вопросов / 10 минут, A–E/навигация/смена ответа, проверка только после
  завершения, повторное открытие результата. Это учебный тайминг, не официальный экзамен.
- Одна таблица timed_blocks со снимками ключа и знакомости, ответами и дедлайном.

  ожидания блокировки, UPDATE ответа дополнительно проверяет дедлайн. Повторное
  завершение не меняет результат. Asyncio уведомляет, PostgreSQL обеспечивает точность.
- Старые назначения считаются консервативной знакомостью; в реальном банке 20 вопросов,
  по 4 есть попытки, все 20 ранее назначены. Блоки не создают учебные evidence/score events
  ЕГЭ и не меняют темы/повторы; экспорт измерений их пока не включает.
- Проверки: 81 backend test локально + 3 PostgreSQL concurrency/migration tests;
  84 passed в новом образе, import-linter 2 kept, frontend build и ruff новых модулей прошли.
  PostgreSQL-тесты используют отдельные схемы с синтетическими данными.
- Миграция b0c1d2e3f4a5 применена, API/бот пересобраны и пересозданы. Proxy HTTP недоступен,
  SOCKS отвергает авторизацию. Рабочий профиль запрошен. Уведомления без durable
  outbox могут потеряться/повториться; сохранённый результат открывается повторно.
  Подробности: `!DOC/architecture/CISIA_TIMED_PRACTICE_V1.md`.
  После миграции/деплоя количество missions/evidence/score_events/review_items
  осталось 88/67/2/48; timed_blocks пустая (ученический блок не запускали).

## 2026-08-13 - Задача без записываемого ответа: ложный провал и формат-гейт

- 11 августа ученица впервые сделала полную пятёрку (~45 мин), включая две новые темы —

- Одна задача засчитана провалом ошибочно: эталон `2/3`, ученица ответила `0,667`.
  Рассуждение верное; 2/3 не записывается в бланк ЕГЭ ни с какой точностью, то есть

- Данные: обе задачи получили корректные числа (0,6 и 0,375) в seed и в БД, ложная ошибка
  снята, карточка повтора возвращена в DONE.
- Проверка: `pytest tests/` → 292 passed (два предсуществующих падения на месте);
  аудит банка 394/394 чисто; `docker compose up -d --build api bot`.

Открытый хвост: LLM-ревьюер написал «Вероятность найдена верно» и одновременно выставил

## 2026-08-10 - Планировщик дня: сгоравший слот и запертые новые темы

Status: ЗАДЕПЛОЕНО (код + данные), проверено живьём.

- Жалоба ребёнка («дриллы те же», «одна задача и больше нет») подтвердилась данными:
  321 APPROVED задача в банке, 18 просроченных повторов — а в день доходило 2-3 из 5.
- Причина №1: в `build_daily_queue` кандидаты обрезались по бюджету до похода в БД, и
  кандидат без свежей задачи терял слот (`continue` без добора). Два неустранимо «сухих»
  кандидата («Логарифмы» — 0 задач в банке; «Кодирование изображений» — 1 задача, уже
  назначенная) были самыми старыми и вставали первыми каждый день.
- Причина №2: `[*due, *back_to_work, *new][:budget]` — повторов всегда больше бюджета,
  поэтому новые темы не попадали в очередь в принципе; повторы отсортированы по дате →
  один и тот же набор тем изо дня в день.
- Правка: `select_daily_queue` отдаёт весь упорядоченный список (обрезание — у вызывающего,
  который знает про наличие задачи), `DAILY_NEW_TOPIC_QUOTA = 1` резервирует слот под новую
  тему, бюджет вынесен в `daily_budget`. Данные: закрыт мёртвый повтор «Логарифмы», сняты
  10 зависших не-daily миссий (июнь-июль), державших темы в `in_work`.
- Проверка: `pytest tests/` → 290 passed; два падения предсуществующие (кодировка в
  симуляторе, Permission в `test_measurement_export`) — воспроизведены на застэшенных
  правках. Живьё: пересобранный день дал 5 задач, впервые с новыми темами.

- Пополнение банка: генератор (`--count 6 --seed 11 --approve`) → +84 по 14 темам, плюс
  +6 вручную в «Кодирование изображений и звука» (ту самую дыру, из-за которой сгорал слот)
  с ответом, посчитанным кодом и прогнанным через формат-гейт грейдера. Итого 90.
- Ребёнку отправлено одно сообщение (`delivered_to_telegram: 1`): её сигнал был реальным
  багом и он починен, что залито в банк, и ответ на её запрос про кнопку «дай похожую».

Открытый хвост: кнопка «сгенерировать похожую в реалтайме» — запрос ребёнка, реализуема
шаблонами `generate_tasks.py` без LLM в контуре (ответ считается кодом), детали в
`ACTIVE_TASK.md`. MCP-сервер держит код момента запуска — после правок его вызовы идут по
старой логике. Правки не закоммичены.
